# M7 configuration grid — run record, 2026-08-24 → (in progress)

The archived record of the M7 grid run. Written so the numbers here can go straight into the
paper's appendix tables, and so a later run can be diffed against this one.

## Where the data is

```
/cluster/arthur/archive/m7-grid-2026-08-27/          231 MB, on shared NFS
├── PROVENANCE.txt        git commit, host, launch time, source dirs
├── COMPLETION.txt        per-config instance counts at archive time
├── results.csv           217835 rows x 272 cols  <- THE table source
├── logs.tar.zst    72 MB raw per-instance .out logs (the primary record)
├── benchlogs.tar.zst 7.5 MB per-column console logs
├── failing-pairs/        derived failure scan (A/B/C/D lists, pairs.tsv, sizes.tsv)
└── MANIFEST.sha256       checksums for all of the above
```

**`/cluster` is shared NFS and persistent. `/scratch` is node-local and has been wiped before**
(2026-07-06, destroying proofs and both binaries). Nothing in this archive depends on `/scratch`.

The proof directories are deleted as the run proceeds, by design. **The per-instance `.out` logs
are therefore the primary record** — `logs.tar.zst` is the irreplaceable artifact here; `results.csv`
can always be regenerated from it:

```bash
julia scripts/aggregate_results.jl <any-proofs-dir> results.csv /cluster/arthur/logs
```

`aggregate_results.jl` enumerates from the *logs* dir, not the proofs dir, and correctly takes the
**last** `=== RUN` block of each append-only log. The proofs-dir argument is used only to resolve
`.err` files, which are mostly gone.

`overwrite` was set deliberately: a 1/60-scale smoke run earlier the same evening left ~1011
`.done`/`.sat` sentinels, and every sentinel check is `!overwrite`-gated, so without it the real
run would have skipped exactly the instances the smoke test had touched.

**`gss` and `gss-noclique` are `proves=false`** — they stop at the tier-1 non-logging solve, which
*is* their table cell. Their result lives in `nopl_verdict`, not `solve_verdict`, so a `-` above is
correct and not a failure:

```
both columns:  UNSAT 21169   SAT 3902   UNKNOWN 519   (of 25590, at stnopl=60)
```

Those two columns produce **identical verdicts on all 25590 instances**, which looks at first like
the `gssbin` silent-fallback bug duplicating a column. It is not: solve *times* differ on 13506
instances (52.8 %), so `--no-clique-detection` is demonstrably active — it just never flips a
verdict inside the 60 s budget. That is itself a reportable result. Both pin revision `2180663`
and `cluster_env.sh` resolves it, so the binaries are correct.

## Failure categories

Counted over instance-config pairs including resolv cores (214410 records).

| | veri full | veri smol | cake smol | pairs | whose bug |
|---|---|---|---|---|---|
| **A** | VERIFIED | **FAILED** | — | 33 | ours (trimmer) — but see below |
| **B** | VERIFIED | VERIFIED | **FAILED** | 3815 | unknown — the two checkers disagree |
| **C** | FAILED | FAILED | — | 896 | **ours (solver)** |
| **D** | FAILED | VERIFIED | VERIFIED | 1945 | **ours (solver)** |

**C and D are both Glasgow bugs.** We maintain the solver, so a proof VeriPB rejects is our defect.
D is *not* a positive result: the trimmed proof certifying means the solver emitted unjustified
steps and the trim deleted them by accident. D measures how often trimming **masks** the bug —
71 % on `gss-nosupp`. Together C+D = 2841 pairs, the largest defect in the grid.

`gss-nosupp` emits a non-certifying proof on **11.3 %** of instances, 50-100x every other column.

**A is stale, not a live bug.** All 33 are `lad-*`, and the LAD columns were never relaunched after
the 2026-08-24 `<=` parse fix, so their last `=== RUN` block is a pre-fix run; 33/33 pass at HEAD.
Glasgow's category A is **zero across ~200000 pair-records** — that is the real result.

**B is the open question**: Glasgow-only, 3815 pairs, VeriPB accepts a trimmed proof CakeML
rejects. `gss-nosupp` scores 0 while `gss-nostaged` scores 1236. Work in progress on branch
`diag/littrim-experiment` (`nolittrim`, `polkeep`, `iakeep`, `iaprop`).

## Traps that cost time on this run — read before the next one

1. **The `[N/25590]` progress line in a benchlog is not progress.** It is block-buffered and was
   17 h stale on one node and 66 h stale on another while both ran normally. Count per-instance
   `.out` files instead (`COMPLETION.txt` shows the one-liner).
2. **Torn NFS appends.** ~1.3 % of pair-records carry a mangled config name (`gssgss-nostaged`,
   `ed`, `D`, `LVgIED`) from concurrent writes. They corrupt any *mean* — an unfiltered mean solve
   time comes out at 22589 s against a 600 s timeout. **Use p90, never mean.** Filter config names
   against the known set before aggregating.
3. **Logs are append-only.** Take the last `=== RUN` block. An earlier block may be a 1/60 smoke run.
4. **The sysimage bakes env-derived paths at build time**, and `build_sysimage.jl`'s staleness check
   is mtime-only, so a wrong-environment image reports "up to date" forever. `run_grid.sh launch`
   now rebuilds unconditionally and verifies with `check_sysimage_env()` before launching anything.
